# 项目选取

输入是第八周选题要求及已核对的候选源码、原测试和目标接口情况。综合近期对业务易懂、规模可控的要求，选择 Smart Library 作为管理系统样例，并保留已有 Java 基线的 Commons IO。每个项目先固定一个能独立理解的测试类。

| 项目 | 固定版本 | 主源码 / 测试源码 Java 文件数 | 选取理由 |
| --- | --- | ---: | --- |
| Smart Library | [a3224ae](https://github.com/violazeneli31/LibraryManagementSystemTesting/tree/a3224ae89ad58bd73721f692d80efe20d794711e) | 20 / 29 | 借阅资格容易按会员状态、上限及逾期情况判断，涉及跨文件的会员模型和政策接口 |
| Commons IO | [2.16.1，290d72e](https://github.com/apache/commons-io/tree/290d72eda9152d1e11b79d48453908ff3f6b9897) | 253 / 260 | 首轮限定 BOM 类型，业务范围集中，包含静态对象夹具和异常用例 |

Smart Library 首轮原测试为 [DefaultBorrowPolicyUnitTest.java](smart-library/src/test/java/smartlibrary/Part3_Testing/Unit/policy/DefaultBorrowPolicyUnitTest.java)，被测实现为 [DefaultBorrowPolicy.java](smart-library/src/main/java/smartlibrary/policy/impl/DefaultBorrowPolicy.java)。相关类型在同一项目的 smartlibrary/model 与 smartlibrary/policy。仓颉填充阶段需要准备相应会员类型和借阅判断。罚款测试含参数表，可在确认参数化预处理后扩展。

Commons IO 首轮原测试为 [ByteOrderMarkTest.java](commons-io/src/test/java/org/apache/commons/io/ByteOrderMarkTest.java)，被测实现为 [ByteOrderMark.java](commons-io/src/main/java/org/apache/commons/io/ByteOrderMark.java)。仓颉填充阶段需要提供真实的 BOM 构造、字节访问、编码名称和比较接口。

输出包括本目录两份固定源码快照和上表的选取范围。上游 README 与已有许可证保留在源码目录。Smart Library 源码快照中未发现独立许可文件，出处按上述固定提交登记。
