## 根因和修改

官方源码位置：
https://gitcode.com/Cangjie/cangjie_runtime/blob/main/runtime/src/os/Windows/WinModuleManager.cpp

ReadWinModuleAtInit()把加载模块链表的第一个真实节点当作停止标记，遍历过程中会读到链表头。当前Windows中链表头的相关字段并非有效名称指针，于是向wcslen传入0x620026并崩溃。

正确语义是：

```cpp
PLIST_ENTRY head = &ppeb->Ldr->InMemoryOrderModuleList;
for (PLIST_ENTRY iterator = head->Flink;
     iterator != head;
     iterator = iterator->Flink) {
    // 保留原有真实模块处理逻辑；不读取链表头的模块字段。
}
```

本机未具备运行库完整源码构建工具链。本次在原始1.2.0SDK的独立副本中做了与上述语义对应的两处机器指令修正，不是从源码重建，也不是官方补丁：

|运行库RVA|原字节|新字节|作用|
|---|---|---|---|
|0x1d908|8b|8d|保留真正的链表头地址|
|0x1d92b|11|04|从“前进并检查边界”开始，跳过头节点|

修复脚本严格限定原始运行库哈希和原始指令字节；不适用于其他SDK文件。原版SDK、Windows DLL和系统安全设置保持不变。
这是课程实验的本地临时方案，适用性只验证了当前最小程序及本批24个参考测试；不应分发为官方SDK或作为生产运行库。上游官方修复后应切回官方版本并重新验证。

## 在其他机器准备独立副本

仅当同样的官方1.2.0运行库出现相同问题，且希望复现实验环境时使用。需要Python3；不能对官方SDK原目录直接覆盖：

```powershell
python .\scripts\prepare-local-sdk.py --source-sdk 'D:\tools\cangjie-1.2.0' --output-sdk 'D:\tools\cangjie-1.2.0-localfix'
```

脚本仅接受指定原始哈希，新目录必须不存在。生成的LOCAL-RUNTIME-FIX.json记录所有改动。
