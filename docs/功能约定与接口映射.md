# 功能约定与接口映射

## 1. 对应范围

|Java|仓颉|约定|
|---|---|---|
|new Rectangle(l,t,r,b)|Rectangle(l,t,r,b)|坐标满足l≤r、t≤b；允许点和线；非法参数异常|
|getLeft/getTop/getRight/getBottom|只读属性left/top/right/bottom|对应同一坐标值|
|intersectsWith(r)|intersectsWith(r)|闭矩形，共享边或角也算相交|
|toString()|toString()|精确字符串[l,t,r,b]，逗号之间无空格|
|InstructionParser.parse(String)|InstructionParser.parse(String)|ZERO=0、INC=1、DEC=-1；其余是带可选正负号的ASCII十进制int32整数|
|parse(null)|parseNullable(None)|参数异常；普通仓颉String不能直接表示null，因此另设Option适配入口|
|new Account(initial)|Account(initial)|初始余额闭区间[0,1000000]|
|getBalance/deposit/withdraw|getBalance/deposit/withdraw|整数单位；每次操作金额必须>0；失败不修改余额|
|InsufficientFundsException|InsufficientFundsException|取款金额>余额时抛出；与参数异常区分|

解析器只以ASCII空格U+0020分隔，连续和前后空格忽略；空串与全空格返回空数组。制表符、换行、中文数字、小数、未知指令、单独的+/-和越界整数不合法。不执行指令，不要求LITERAL等操作数结构。

账户存款不能超过余额上限；先判断再更新，避免加法越界。取款恰好等于余额时允许取完。测试不涉及数据库、并发、浮点货币和日志。

## 2. 测试语义映射

|JUnit|仓颉参考检查|说明|
|---|---|---|
|@Test方法|@Test类下的@TestCase方法|每个样例编号一一对应|
|assertEquals(expected,actual)|@Expect(actual,expected)|保留两个值的角色；不是仅替换名称|
|assertTrue/assertFalse|@Expect(value,true/false)|检查同一布尔条件|
|assertArrayEquals|先@Assert长度，再逐元素@Expect|检查内容和顺序；长度不同先停止，防止越界|
|assertThrows(Expected.class, action)|try/catch指定异常类型后检查caught=true|未抛异常会失败，其他异常不会被吞掉；不检查消息|
|@BeforeEach setUp|每个账户测试方法开始创建Account(100)|保留独立初始化，避免共享可变状态|
|prepareSequence辅助方法|prepareSequence(account)|保留存50→检查150→取20→检查130的调用与断言顺序|

## 3. 语言差异与限制

Java业务整数和数组为int/int[]；仓颉使用Int64/Array<Int64>便于初学者阅读。对应输入域限定Java int范围，解析结果显式限制int32，账户余额限制1000000。不能据此声称任意Int64输入都与Java等价。

Rectangle的null参数行为不在本批对应范围；未研究对象身份、浮点容差、Unicode和本地化格式。P09只研究输入缺失值。
新编样例不代表真实项目复杂度；24个测试通过也不证明所有输入完全等价。仓颉测试是参考检查，不是独立可信的标准答案；最终状态以实际运行记录为准。
