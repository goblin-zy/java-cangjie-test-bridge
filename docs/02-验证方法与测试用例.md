# 验证方法与测试用例

## 1. 上下文工具的7项边界测试

实现位于 `week7/context-validation/tests/test_context_lookup.py`。每个用例在临时目录构造最小 Java 源码、快照与选择配置，结束后清理临时数据，不修改提交的历史证据。

|测试方法（去掉 test_ 前缀）|输入/操作|应该看到什么|防止什么问题|
|---|---|---|---|
|utf16_offsets_after_chinese_emoji_and_crlf|中文、emoji、CRLF 后定位方法|导出正文准确，原始字节保留，Markdown含完整类|Java UTF-16偏移与Python字符位置不一致导致截错代码|
|changed_live_source_rejected|索引后修改现场源文件|报 Stale，且不创建输出目录|拿旧索引拼接新代码|
|modified_snapshot_rejected|修改冻结快照|报 Stale|证据副本被改写仍当作原始来源|
|duplicate_symbol_not_silently_overwritten|索引加入重复同名条目|报 Ambiguous|歧义成员被静默覆盖|
|unknown_dependency_not_invented|选择不存在的 Missing#run()|报 not found|生成没有源码依据的片段|
|existing_delivery_not_overwritten|向同一目录重复导出|拒绝，原JSON字节保持一致|覆盖上一轮证据|
|path_escape_rejected|传入 ../outside.txt|报 escapes|越出声明的源码根目录|

## 2. 九条账户参考测试分别说明什么

入口 `evaluate_account.py` 的 NAMES 是预期方法清单，Java原测试在 `week7/src/test/java/study/translation/AccountTest.java`，仓颉参考测试在 `week7/reference/cangjie/tests/account_test.cj`。具体输入、金额和断言以这两个文件为准，不能只按方法名猜测结果。

|方法|阅读重点|
|---|---|
|testInitialBalance|构造后的初始状态与余额读取|
|testDeposit|存款后余额更新|
|testWithdraw|合法取款是否正确扣减|
|testWithdrawAll|取出全部余额后的边界状态|
|testSequence|连续操作及辅助检查中的中间断言|
|testInsufficientFunds|余额不足异常，以及异常后的状态与后续操作|
|testInvalidAmounts|非法金额输入的异常约束|
|testBalanceLimit|余额限制及越界行为|
|testInvalidInitialBalance|构造参数的合法范围|

已有证据：[九条参考测试报告](../week7/context-validation/validation/repository-account-preupload/execution/report.md)。需同时检查预期9、发现9、执行9、通过9，不能把空测试运行当作通过。该日志属于上传前历史运行；本次是否重跑见整理验证记录。

## 3. 历史故障场景怎么读

`validation/evaluation-history/` 保存13组历史场景。它们用于验证评价器，不是13个翻译成功样本。每组先看配置与源码，再看 report.md/results.json，最后定位阶段日志。

|场景|预期分类/核对重点|
|---|---|
|正确实现|编译、发现、执行都成功且清单一致|
|错误业务导致断言失败|运行失败须保留失败断言，不能改期望使它通过|
|意外异常|与普通断言失败区分|
|编译错误|停止在编译阶段，不编造执行结果|
|零测试、跳过|不得当成完整成功|
|过滤遗漏、错误预期清单|比对身份与数量，识别未覆盖的方法|
|缺失文件、缺失环境|报告输入/环境失败，不能归咎业务语义|
|数量模式、数量不符|没有完整身份时明确限制，数量不一致须失败|
|第二种样例、超时|检查执行器是否适用于其他输入，以及阶段超时是否保留证据|

完整分类、字段和历史说明见[评价验证方法](../week7/context-validation/docs/评价验证方法与交付说明.md)及[评价输出格式](../week7/context-validation/docs/评价输出格式说明.md)。原版SDK与localfix必须分别记录。即使全部检查通过，也只能支持已运行场景的可执行性，不能证明两种语言对全部输入语义等价。
