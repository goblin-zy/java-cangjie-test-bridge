# 两项任务交付核对与限制

|要求|当前交付|
|---|---|
|输入Java文件或目录，不能绑定类名／样例编号|通用CLI及PowerShell包装；现有3类、单文件和其他名称结构样例均实测|
|保留包、导入、声明、字段、初始化和签名／注解|AST定界，只替换方法体；显式构造器委托保留|
|保存原方法体并区分角色|members.json的original_body、role、签名、来源和骨架位置|
|重载等成员可对应与找回|文件、限定类名、方法名及参数语法构成id；回填后原始字节哈希一致|
|实际输出及核对|generated/及validation/extractor-003/；见骨架核对记录|
|可用于验收的参考仓颉测试|3份业务源码、3份参考测试、24条场景索引及两侧行为核对|
|参考材料实际可执行|Java24通过，仓颉localfix24通过，发现和执行数量均核对|
|基本错误检测能力|4个独立可构建错误版本被相关参考测试发现，正式源文件与测试未改|

需要明确的限制：

1. 提取器执行语法分析，不执行完整符号绑定，不分析跨文件依赖闭包、继承生命周期或组合注解实际运行语义。当前主要支持Java17与普通JUnit Jupiter结构；其他写法要按诊断和文档核查。
2. 骨架不恢复测试行为。字段／静态初始化仍可能含可执行语句，骨架方法则抛占位异常；不得拿骨架作为测试正确性的运行证据。
3. 仓颉基线使用localfix而非原版SDK。这个前提和哈希必须随结果共享，后续换环境需复测。
4. 24个场景和四个业务错误仅提供有限验证证据；参考测试不等于绝对标准答案，差异需回到Java原测试和功能约定确认。
5. 规则映射、项目材料生成、上下文查找、模型翻译、意图核验提示词和通用对照平台由其他模块衔接，本交付没有冒充已完成这些工作。

本目录作为第七周交付材料。交接时建议共同固定输入根目录、成员id格式、输出schema_version和SDK运行库标记。
