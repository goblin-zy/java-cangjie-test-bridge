# Java 骨架提取器源码讲解

实现集中在一个 Java 文件中。先看 `main()` 如何串起读取、解析和写出，再进入内部类 `Collector` 看成员是怎样记录的。[源码](tools/JavaTestSkeletonExtractor.java)

| 代码 | 负责什么 |
| --- | --- |
| `main()` | 解析命令行参数，找到输入文件，保存原文。调用 `JavacTask.parse()` 生成语法树，把树交给 `Collector`，然后按位置替换方法体并输出结果。 |
| `Collector.visitClass()` | 记录类名、类型和位置，维护嵌套类的所属关系。 |
| `Collector.visitVariable()` | 记录类字段的类型、声明和初始化表达式。 |
| `Collector.visitMethod()` | 收集方法或构造器签名，根据注解推断成员角色，从原文件截取方法体，并创建占位替换记录。 |
| `Collector.resolve()` | 根据注解写法、导入和本文件的类型名推断注解来源。当前实现未执行完整的符号绑定。 |
| `Edit` 和 `map()` | `Edit` 记录原源码替换区间及替换文本，`map()` 将原文偏移换算成骨架文件中的偏移。 |
| `write()`、`sha()`、`json()` | 分别负责写文件、计算 SHA-256 和生成 JSON。 |

以 `canBorrow_returnsFalse_whenMemberIsNull` 为例，`visitMethod()` 通过 `n.getBody()` 获取方法体节点，用节点的开始和结束位置执行 `source.substring(bs, be)`。借阅调用和断言因此进入成员表的 `original_body`。扫描结束后，主程序才应用 `Edit`，把这段方法体换成占位异常。可逐份对照 [Java 原测试](../../样例材料/骨架样例输入/smart-library/DefaultBorrowPolicyUnitTest.java) · [Java 骨架](../../运行记录/骨架样例/smart-library/skeleton/DefaultBorrowPolicyUnitTest.java) · [成员表](../../运行记录/骨架样例/smart-library/members.json)

一个已复现的优化点是测试角色识别。Aho-Corasick 的 37 个 JUnit 4 `@Test` 方法在现版中提取成功，但成员角色被标成 `helper`。若要支持这类样例，改动点在 `resolve()` 和 `visitMethod()` 的注解判断。验收可比较同一原测试修改前后的成员角色，并核对 `original_body` 保持一致。
