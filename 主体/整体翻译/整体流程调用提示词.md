# 整体流程调用提示词（参考）

本提示词整理自此前实际项目的整体调用说明，入口按本分支第二版统一，用于组织一次新任务。它不是历史项目答案，也不是可直接传给程序的配置。

```text
请使用当前分支和项目仓库，实际完成一次 Java 测试到仓颉测试的整体翻译：
https://github.com/goblin-zy/java-cangjie-test-bridge

先阅读各部分说明，记录 Java 骨架提取、转换规则、项目公共材料、仓颉骨架及成员映射的真实入口。已有本地仓库时优先使用本地代码。上下文工具和整体提示词使用本分支第二版，其他部分使用仓库的实际交付。

本次可选择样例材料/Interval双语项目：java 是完整源项目，cangjie/src 是实际目标业务源码，所选测试类为 org.ahocorasick.interval.IntervalTest。若用户另有指定项目，以其范围为准。不要读取运行记录/已有整体翻译样例中的译文作为生成答案。

1. 阅读 主体/集成适配/README.md，核对本分支集成的蔡俊杰 week12 工具。需要继承测试入口时先用 JavaTestSkeletonExtractor 对包含基类的源码范围提取，取得 members.json；提取不依赖上下文或公共材料。
2. 将完整 Java 项目交给 context_tool.py build --project，明确 --test-scope 和必要根目录；同版成员表通过可重复 --java-members 传入。输出到新目录，再为所选执行测试类运行 suite。先读 agent_context.json/tasks.json，聚焦单条同时读 tests 文件和 shared_ref 的共享材料。没有成员表也可建基础索引；晚到的成员表要用于分析时须重建新索引。
3. 按对应模块准备规则、公共材料、仓颉骨架和映射，核对与 source/ 同版。骨架生成读取已适配第二版上下文的提示词。用 prepare_skeleton_check.py 把实际整体任务复制为检查目录，再用 check_skeleton.py 做填充前结构检查，传入真实业务源码并保存报告。whole_task 与检查器原生配置不是同一种文件。公共材料和仓颉骨架不成为源码索引的前置条件。
4. 进入整体翻译时读取 主体/整体翻译/translate_whole.md，并按 主体/config/whole_task.template.json 整理真实路径。Interval任务示例.json 仅填了可确定的项目入口，其余 null 必须根据实际交付补齐，不能假装材料已存在。
5. 从 test_structure 了解内部步骤入口；有疑问时用 analyze 查询测试或辅助成员，保留控制区域、断言依据、同名候选与延迟执行边界。用 features 查询需复核结构，再按需 read/references/resolve/resources/file 补查。
6. 对齐上下文 key、Java 源成员 ID 和仓颉目标映射。字段可能分别记录具体变量与整条声明，结合文件摘要、所属类型、名称/类型、区间及原文核对。不要只按方法名、行号或字段区间相等配对。
7. 对照实际仓颉业务的包、成员、参数和行为，翻译完整类。按成员保存真正使用的规则/材料/源码证据；新增辅助声明独立说明必要性、委托对象和检查状态。
8. 保存候选译文、必要资源和整体提示词要求的交接记录，报告实际完成范围、问题和待核验项。未解析、预算缺项和共享内容不可默认为已处理。

请实际运行本地程序并生成译文，不止给出计划。源代码转换、可执行测试前缀和完整运行时控制流不支持，不调用不存在的步骤。普通程序和当前 Agent 完成工作，不接模型 API 或服务器。

默认先完成翻译及静态交接；用户本次要求复测时，在副本实际编译和执行，并记录范围及日志。没有执行的 Java/仓颉编译和测试标为 NOT_RUN；已有译文的通过记录仅是历史样例。最后给出真实输出路径、材料衔接、采用的暂定接口和具体缺项。
```
