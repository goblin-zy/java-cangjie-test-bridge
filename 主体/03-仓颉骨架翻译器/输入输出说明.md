# Java 到仓颉骨架翻译工具的输入和输出

当前正式版由模型按提示词生成仓颉骨架。提示词是实际的转换规范。检查脚本读取生成产物，执行样例核对。[骨架翻译提示词](骨架翻译提示词.md) · [检查脚本](check_skeleton.py)

| 交给模型的输入 | 用途 |
| --- | --- |
| 本次任务配置 | 确认输入范围、目标包、输出位置、工具链版本及允许复用的定义。 |
| Java 骨架、`members.json`、提取报告 | 确认类和成员的声明、角色、签名、位置及已有诊断。需要时读取原始源码。 |
| 通用规则、项目约定、当前测试上下文 | 确认 JUnit 到仓颉的框架转换、目标业务类型和接口，以及字段、基类、辅助方法等关系。 |

| 新版提示词约定的输出 | 内容 |
| --- | --- |
| 仓颉 `.cj` 骨架 | 目标包、导入、类、字段、方法声明及测试注解。待填方法体使用明确的占位标记。 |
| `member_mapping.json` | 记录源成员 ID、目标签名与位置，并标明后续要填方法体还是字段初始化。 |
| `translation_report.json` | 记录转换依据、结构调整、未解决项和核验结果。 |
| 检查记录与交接说明 | 记录实际执行情况及所需补充材料。 |

目录所带的两份 `.cj` 和成员表来自前一版提示词，其检查脚本使用较简的映射字段。新版提示词中新增的翻译报告尚未随这批样例交付。[生成记录](../../运行记录/骨架样例/生成记录.md) · [文件讲解](源码解释.md)

在交付根目录执行下面这条命令可以复核两份已有骨架。它会重新写出 `运行记录/骨架样例/` 中的 `member_mapping.json`。

```powershell
python "主体/03-仓颉骨架翻译器/check_skeleton.py"
```

该命令读取两组 Java 成员资料和现有仓颉文件。新的骨架由模型按照提示词生成。
