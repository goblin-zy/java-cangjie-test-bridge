# 单个测试片段的翻译提示词

材料 2.0 统一读取 C03「目标接口约定」的对应、签名、调用形式及行为；材料 1.0 仍分别读取 C02、C03、C04。按条目 ID 引用同一快照，区分实现证据与 pending 拟议约定。骨架、整体译文与各片段采用同一签名；冲突写入交接记录，未覆盖的调用回查源测试并补充约定。

材料包中的 Java 覆盖条目用于复核对应测试实际执行的业务实现。结合样例上下文和原始代码判断这些实现与当前片段的关系。整次测试的覆盖可能来自初始化、辅助方法或清理。片段逻辑、调用顺序和断言以源码为准。材料包标明覆盖缺失或失败时，保留该状态并按现有静态依据处理。

1. 读取 `next` 返回的材料包。确认任务编号、目标签名、槽位、待翻译 Java 原文和参考材料。结合生命周期、辅助方法和资源理解测试开始时的状态。
2. 按同一仓颉骨架的名称和签名翻译当前槽。业务代码用于核对调用，目标接口暂定时沿用共用骨架的约定并登记。保留原操作、顺序、断言的预期与实际值、异常类型及触发范围、清理行为。
3. 方法体槽返回外层花括号内的代码。字段槽返回初始值表达式。沿用目标声明，只提交当前槽内容。发现缺少关键材料时向编排方报告具体原因，由其补查或调用 `block`。
4. 保存 JSON 到片段输出目录的 `submissions/<任务编号>.json`，使用本次 `next` 返回的任务编号和摘要。导入项仅写路径，例如 `std.unittest.*`。有暂定接口或其他待确认项时列入 `unresolved`。

```json
{
  "task_id": "T03",
  "packet_sha256": "<next 返回的摘要>",
  "code": "<仓颉方法体内部代码或字段初始值>",
  "imports": ["std.unittest.*"],
  "unresolved": []
}
```
