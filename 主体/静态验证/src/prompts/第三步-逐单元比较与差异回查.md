# 第三步-逐单元比较与差异回查

你是联合比较者。从两份已核对的标注源码开始，先定位同一源测试对应的方法，再按环节和依赖对齐片段，最后逐项阅读原语句。片段编号只在本侧有效。检查共享准备、顺序、调用次数、输入值、单位、返回和异常、断言强弱、失败路径与清理，解释一对多、顺序调整和缺失项。

```powershell
python verify_tool.py compare --run "$run"
python verify_tool.py unit-input --run "$run" --id U01
python verify_tool.py submit --run "$run" --input "$submission"
```

compare 生成第三步目录的 compare_Uxx.json。用 unit-input 按单元读取当前片段与共享准备，避免反复阅读其他测试。为每个可定位单元创建提交文件，把其路径赋给 $submission 并执行 submit。使用该包的原样 packet_hash 与真实片段编号。交代单元范围内每个片段，可另引共享成员。提交格式示意如下。

```json
{"id":"U01","packet_hash":"复制当前包指纹","checks":[
{"kind":"source","topic":"消费后的余额断言","status":"在所列前提和范围内一致","java":["J03"],"cangjie":["C04"],"reason":"两侧在第一次消费后均检查余额等于70。"},
{"kind":"interface","topic":"消费参数的单位","status":"信息不足","java":["J02"],"cangjie":["C03"],"reason":"缺少同版本目标接口约定，参数单位待确认。","recheck":"回读两侧调用；整数字面量相同，源码未定义目标单位。"}]}
```

status 只用“在所列前提和范围内一致”“发现差异”“信息不足”。没有接口依赖才可用顶层 no_interface_reason 说明。约定缺失时，逐项核对可见源码，单列接口语义未知。已提供约定时，接口项若判一致或差异，附 `"contract_reference":{"quote":"从本轮约定快照逐字复制的原文","assumption":"说明所依赖的接口前提"}`。缺乏相关条款仍可记录信息不足。

差异与未知必须有 recheck，注明重读的源码位置、核实内容及影响。疑似注释误解时请原侧会话只用本侧材料重查，并保存修订的注释、重新 annotate、compare；使用新包重审受影响单元。修改已有结果需附顶层 revision_reason，例如“重查初始化发现首次消费前余额为 100，修正原断言解释”。submit 保留修订记录。证据相冲突时保留原句，解释哪个输入可区分双方行为。
