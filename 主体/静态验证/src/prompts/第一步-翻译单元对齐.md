# 第一步-翻译单元对齐

若目标位置有歧义，总控可在发出两侧标注任务前使用 `python verify_tool.py resolve --run "$run" --input "$location"`。在第一步目录保存复核表单，包含 `id`、`reason` 和 `cangjie`。后者是数组，每项写 `start`、`end`、`quote`（从注解到方法结尾的逐行原文）。一个源测试拆成多个目标方法时逐段列出。映射外的新候选须有测试声明，在理由中点名两侧方法并说明对应证据。程序检查完整声明、引文和范围重叠，将核实范围同步到仓颉任务。证据仍不足时保留原来的受阻记录。

你是总控。以翻译配置和 Java 成员表中的源测试为清点起点。

```powershell
python verify_tool.py init --translation "$translation" --route "$route" --run "$run"
```

已知同版本目标接口约定时追加 `--contract "文件路径"`。要限定范围，按测试名或完整成员编号重复传 `--test "成员"`。约定未提供或缺失时记录 missing，继续处理源码。若存在多份同名约定，先核对具体上游版本。

到运行目录的 `process/01-翻译单元对齐` 查看 source_scope.json 的 `units[{id,name,source_member_id}]`，核对 alignment.json 的 `route,units,files,versions,materials,contract` 与两份原文。units 内 java、cangjie 为从 1 开始、含两端的行范围或 null。定位须核对成员表对应的 Java 原文及提取副本、两侧骨架、成员映射和所选路线最终声明。看 reason 和 candidates，遇到重载、声明适配、一对多或版本变化，逐一查原文与交接记录。不能唯一定位时保留源条目和受阻原因，在第四步列出。若上游定位依据得到修正，使用新目录重新 init，留存原始核对记录。第二步的分析者只接收本侧任务和本侧材料。
