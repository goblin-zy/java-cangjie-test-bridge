# 第四步-结果清点与按需回查

你是总控。以第一步 source_scope.json 的稳定成员身份核对本轮所有输入，检查第三步实际保存的结论。

```powershell
python verify_tool.py audit --run "$run"
```

读取“process/04-audit/completeness.json”。已比较的单元还可能含差异或未知。遇到“漏做”，回第三步提交该项，重新 audit 直到所有可定位单元有记录。遇到“定位受阻”，记录缺少的声明或无法区分的候选；新证据可解时从第一步重新定位。旧包指纹或原文核验失败时，先更新相关注释、比较包和提交。

检查共享字段、准备/清理函数、资源副作用是否可能改变多个测试的结论。已覆盖且前提一致时复用已核对证据；发现跨测试冲突时注明成员、行号和受影响单元，回读后修订已有提交；无法解决则保留待确认。将决定写成 JSON，并把文件路径赋给 $decision。action 可取“复用已有依据”“已补查”“待确认”；后两种必须列出 affected。

```json
{"action":"已补查","affected":["U01","U02"],"reason":"写明共享成员、两侧具体位置、对两个结论的影响及相应修订。"}
```

当 action 为“待确认”，回第三步给每个已比较的受影响单元增加一条 status 为“信息不足”、class_review 为 true 的检查项，写出引用与回查依据，带 revision_reason 重新提交。audit 做初次清点。第五步 summary 会重查结果并把该决定写入 completeness.json。
