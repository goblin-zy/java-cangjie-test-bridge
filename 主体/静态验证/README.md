# 静态验证的输入输出与位置

本模块来自 hzy-week11-Static-Validation。它在最终译文生成后，由 Agent 审阅测试语义，程序核对来源、引文、版本和完成范围。核心流程仍为对齐、单侧标注、比较回查、清点和报告。

## 输入文件

| 输入 | 内容与用途 |
| --- | --- |
| Java 原项目与 members.json | 确定本轮源测试、原文位置和源成员身份 |
| Java/仓颉骨架及 member_mapping.json | 查找两侧对应声明，保留原成员 ID |
| 整体翻译的最终 .cj | 实际待验证对象，不使用占位骨架代替 |
| agent_context.json、tasks.json、shared.json、tests/*.json | 第二版上下文，核对共享/逐条摘要及同轮身份，供 Java 单侧和联合比较取材 |
| 两侧实际业务源码 | 分别放入本侧材料，解释构造器、调用与返回行为 |
| 可选接口约定 | 联合比较时引用实际条款；文件存在仍只表示有本轮假设，缺项保留未知 |

由 Agent 按整体任务配置整理实际入口，再用 [静态验证适配程序](../集成适配/prepare_static_validation.py) 接收整体任务、最终译文目录和新的准备目录。适配器复用骨架来源校验，保存副本，生成验证器可直接读取的 translation_config.json。它不会生成模型注释或静态一致结论。

## 输出文件

| 位置 | 内容 |
| --- | --- |
| process/01-alignment/ | 源测试清单、执行/声明身份、两侧原文与对应位置 |
| process/02-annotations/Java、Cangjie/ | 本侧材料白名单、模型标注、补查记录、带注释源码及行号还原表 |
| process/03-comparison/ | 每条测试的比较包、提交、结论和修订/回查记录 |
| process/04-audit/ | 漏做、已比较、定位受阻的清点，以及类级补查决定 |
| deliverables/ | report.md、report.json、两份带注释的源码 |

```text
Java 提取 + 上下文索引/初始材料
  → 生成仓颉骨架 → 填充前结构检查
  → 整体翻译，保存最终译文
  → prepare_static_validation：核对来源并准备文件
  → init：定位与清单
  → 两侧独立分析/annotate → compare/submit
  → audit/summary/deliver
```

正常语义审阅按 [总控提示词](src/prompts/验证总控提示词.md) 使用两个独立、仅接收本侧材料的会话。程序不会创建会话，也不能替代宿主保证隔离。接口不清楚时先查询真实业务及上下文，再决定条款或未知项。

当前每轮处理一对测试文件。week12 的执行类关联可读入；跨文件基类方法会列入清单并明确定位受阻，尚未支持跨多个原文件插注释。普通 JUnit 3/4 和已登记的 test_* 角色进入筛选；参数化/动态测试的运行实例语义仍需相应材料和人工判断。

原工具命令和各步提交格式见 [详细说明](src/README.md)。可搬迁的钱包回归输入位于 [样例材料](../../样例材料/静态验证钱包/README.md)，本次 Interval 整合结果见 [复测记录](../../运行记录/静态验证整合复测/README.md)。
