# 第二步-单侧结构分析与注释

总控在自己的环境执行以下命令，将任务清单与按编号取出的材料正文发给无文件工具、无历史的本侧会话（仓颉换成 cangjie）。0 号是待标注源码；其他材料按实际白名单编号取用。记录发给每一侧的材料编号，等待其返回实际使用记录。单侧会话无需获得公共根目录权限。

```powershell
python verify_tool.py side-input --run "$run" --side java
python verify_tool.py side-input --run "$run" --side java --index 0
```

你是单侧源码分析者。你的输入限于本提示词、本侧 task、materials 清单及清单内文件。按 task 的 source、units 和原始行号定位测试。先读源码，再沿字段、生命周期、辅助函数查初始状态、调用参数、返回值、异常及副作用，必要时读本侧业务源码或已有覆盖。覆盖记录只提示可能执行的方法。把缺少的材料和受影响判断记进 unknowns。

按原文顺序划分能解释的最小片段。包含测试依赖的共享成员，覆盖每个选定测试。说明每次动作与检查的关系；一行同时进行调用与断言时，可用主环节加全角括号中的辅环节。固定环节为“初始化与准备”“被测操作”“结果检查”“清理”。未出现的环节留空缺，避免补造。每个片段七个中文字段均填写单行文字，编号在本侧唯一。

返回 annotations_SIDE.json（数组）和 context_SIDE.json（对象）；SIDE 取 java 或 cangjie。下例的引文、行号和清单路径须换成本次实际值，quote 保留缩进和整行，跨行以换行连接，范围含首尾、严格递增、不重叠。

```json
[{"start":24,"end":24,"quote":"        assertEquals(70, wallet.balance());","片段编号":"J03","环节":"结果检查","维度":"断言与状态","内容":"读取余额并要求等于 70","关联":"检查上一步消费后的状态","依据":"本侧测试原文第24行","待确认":"无"}]
```
```json
{"sources":[{"file":"inputs/0/PointsWalletTest.java","reason":"核对消费后的余额断言"}],"unknowns":[]}
```

总控把两份返回文件放入本轮“process/02-annotations/Java”或“仓颉”目录，再执行本侧命令。核对 edit_check.json、source_locations.json 和标注源码。修正引文时以本侧副本为准。

```powershell
python verify_tool.py annotate --run "$run" --side java
python verify_tool.py annotate --run "$run" --side cangjie
```
