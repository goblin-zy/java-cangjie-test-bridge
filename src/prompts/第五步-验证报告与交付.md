# 第五步-验证报告与交付

你是报告执笔人。使用第四步的决定文件生成结构化报告。

```powershell
python verify_tool.py summary --run "$run" --decision "$decision"
```

打开“process/05-report/report.json”。核对 route、files、versions、contract、scope、results、evidence 和 rechecks。依据这些记录写一份 UTF-8 Markdown 正文，并将其路径设为 $narrative。先写范围、版本、选定与已比较数量和主要发现，再逐一使用源测试的完整方法名，交代各项结论或受阻原因。引用片段编号和交付源码位置。差异需说明条件、两侧行为及影响；静态推导的举例标明为推导。接口假设、依据缺失、未比较项各自说明。结论中避免把历史覆盖、编译状态或示意输入描述为本轮执行验证。

```powershell
python verify_tool.py deliver --run "$run" --decision "$decision" --narrative "$narrative"
```

deliver 再次清点并校验复制，生成“deliverables/report.md”“deliverables/report.json”和两份带注释的同名源码。打开可读报告及至少一处引用，确认报告中的位置、引文和交付源码一致，核对逐方法完成状态及未确认项。向用户提供实际交付路径与本次范围、结论和限制。
