# 步骤设计

## 输入与功能位置

输入为完整代码库根目录，包括源码、测试、构建文件、资源和工程文档。输出目录位于代码库外，使用新名称，避免覆盖既有材料。

```text
完整代码库 → 预处理 → 材料分类 → 翻译骨架 → 测试翻译与验证
```

预处理为下一步提供可读取的工程材料，不依赖逐测试上下文选择工具，也不提前判断每个文件的最终材料角色。

## 程序处理

1. 清点文件和目录，记录相对路径及处理状态；Git元数据、构建产物、链接及部分疑似密钥文件按规则排除。
2. 保存原字节副本与摘要，将同一轮文件固定为一个版本。
3. 静态读取Maven模块、依赖及部分源码根声明；对Gradle等动态配置记录限制，不执行构建脚本。
4. 通过JDK语法树提取Java类型、方法、字段及导入信息；语法错误保留文件并记录问题。
5. 生成统一入口、问题清单和Agent可读取的源码分片。

## Agent补充说明

Agent依据本轮材料说明仓库概况、目录作用、构建入口和未知项，并引用实际文件。程序检查JSON结构、版本、引用与分片摘要后附加说明。引用存在不代表解释正确，读取清单也不构成阅读真实性认证。

Agent说明为可选项；未提供时，程序结果仍可交给材料分类。当前程序不直接调用模型API，任务通过具备本地文件访问能力的Agent执行。

## 实现与限制

Python负责文件整理、版本校验与交接；Java适配器只进行语法解析，未实现类型绑定、完整调用图、继承与资源关系分析。结构ID由文件及源码位置组成，仅在同一快照内稳定。

Maven只读取字面XML声明，不计算完整effective model、属性继承和profile；源码目录提示不等于最终分类。非UTF-8文件保留原字节，不强制当作文本；缺JDK时仍保存文件并记录结构提取未完成。

文件内容与部分结构清单在内存处理，当前未开展大型项目性能评测。敏感文件排除为启发式规则，向外部Agent提供材料前应确认输入范围。
