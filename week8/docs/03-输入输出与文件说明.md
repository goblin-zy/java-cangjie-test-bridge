# 输出给下一步什么

最重要的交付是**完整结果文件夹**，入口为handoff.json。预处理完成后即可交给材料分类，无需逐文件审批。

|文件或目录|通俗说明|下一步用途|
|---|---|---|
|handoff.json|本轮材料的目录索引|知道版本、材料位置和有没有Agent说明|
|下一步材料说明.md|人可读的交接说明|快速理解材料包|
|facts/snapshots/|原仓库文件的副本，保留相对路径|分类时读取真实代码与配置|
|facts/files.json|哪些文件被读取、排除或未能读取|检查范围与文件来源|
|facts/project.json|程序可直接读到的模块和依赖声明|理解工程组织，保留未解析限制|
|facts/symbols.json、relations.json|Java声明及导入信息|为分类和后续步骤减少重复查找；不是完整调用图|
|facts/issues.json、manifest.json|问题、版本、摘要和工具限制|遇到缺失或解析失败时据实处理|
|agent-input/|Agent阅读用的分片清单与内容|便于分批读取整个仓库，不静默截断|
|给Agent的任务.txt、agent-output-template.json|可选说明任务和输出格式|约束Agent输出，不要求自由发挥或生成分类|
|agent-notes.json（可选）|仓库概述、目录/构建说明、未确定项|为下一步提供解释建议，区别于程序事实|

handoff的next_step固定为material_classification，供材料分类读取。agent_status=NOT_PROVIDED表示尚未补充；REFERENCES_CHECKED表示版本及引用通过检查，不代表内容被人工批准。
