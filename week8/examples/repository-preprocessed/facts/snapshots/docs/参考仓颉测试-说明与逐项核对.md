# 参考仓颉测试说明与逐项核对

参考集由已有第六周Java/JUnit样例及已准备的仓颉业务、测试整理而来，本次重新验证，不是模型翻译结果。共3模块、24个测试方法。一个方法中的循环、多组输入和多个断言仍计为一个测试方法。

## 材料位置

- Java实现、JUnit测试和pom：src/。
- 仓颉业务：reference/cangjie/implementation/。
- 仓颉参考测试：reference/cangjie/tests/，三个*_test.cj文件。
- 逐项输入／步骤／预期索引：reference/cases.json。
- 编译、发现、执行和结果：validation/reference-normal-001/。

## 两侧表达对应及人工核对原则

- Rectangle：Java getter对应仓颉只读属性；共享边和角均算相交，构造参数合法性与字符串格式一致。
- InstructionParser：Java assertArrayEquals对应仓颉先@Assert长度再逐元素@Expect；检查内容和顺序。Java null对应仓颉parseNullable(None)，空串仍返回空数组。
- Account：Java@BeforeEach每次建余额100的新账户，仓颉在每个方法中显式新建；A08重新设置为999999。A05保留helper里的150、130及最后120检查；A06保留指定异常、失败后100及后续取款后60检查。
- Java int使用仓颉Int64承载，但约定输入范围仍为Java int；解析器显式限制int32，余额限制1000000。未证明任意Int64输入与Java溢出语义等价。
- JUnit异常断言与仓颉指定类型捕获相对应；本基线不检查异常消息，不额外证明任意自定义异常继承体系的所有行为。

## 可信度与限制

参考测试提供较可信的核对材料，不是绝对正确的金标准。两侧在24个已检查场景上表现符合预期；还用4个有针对性的错误实现检查了发现能力，见另一份报告。未覆盖浮点容差、一般对象身份、反射、Mock、复杂资源及所有输入路径。

参考测试与正式正常业务文件在改错验收中保持原样；错误仅发生在独立副本。用于评价生成测试时，先确认测试场景对应，不要求参考集额外覆盖的场景也必须由待评估测试覆盖；不将完整参考答案直接泄露给被评估模型。
