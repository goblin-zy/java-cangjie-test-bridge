# 下游模块使用说明

## 1. 统一交接约定

预处理方交出整个本轮目录。接收方以该目录为根读取 handoff.json，按其中相对路径定位文件，按相对路径访问材料。

接收顺序：检查 FAILED.json → 读取 handoff 的状态及范围 → 阅读 capabilities 与 issues → 核对 inventory 与 manifest → 按职责取材。材料问题登记后申请补充或重新生成。

源文件按 input/加源工程相对路径定位。members 的位置单位是 UTF-16 代码单元、区间采用左闭右开形式，截取含补充平面字符的原文时按UTF-16单位处理。优先使用成员记录中的 original_source 原文，同时保留整文件上下文。source_member_key是本快照内身份，与其他工具的id须显式对照。source_mapping是恒等来源对应，目标位置对应由骨架模块提供。

下游产物写到独立目录，保留冻结输入原状。源测试变化时重新预处理。目标接口、业务契约与框架资料作为下游额外输入，标明来源。

## 2. 模块输入输出对照

**上下文查找**

- **读取预处理材料**：external_references、test_structure、members、input、issues
- **还需补充**：当前任务、允许访问的上下文源、目标接口或契约
- **应交付**：检索上下文、来源定位、待解析事项

**Java骨架提取**

- **读取预处理材料**：input、members、test_structure、inventory、issues
- **还需补充**：现有提取器与接口要求
- **应交付**：Java骨架、原成员到骨架位置的对应

**仓颉骨架生成**

- **读取预处理材料**：input、members、test_structure及已有成员映射
- **还需补充**：目标类型与接口对应、仓颉规则；采用骨架流水线时的Java骨架
- **应交付**：目标声明骨架、源成员到目标位置的映射、接口缺项

**整体翻译**

- **读取预处理材料**：完整input、members、external_references、issues
- **还需补充**：目标接口或仓颉业务实现、转换规则、流程要求的目标骨架
- **应交付**：完整译文、资源安排、缺项与翻译记录

**片段翻译**

- **读取预处理材料**：members、input、test_structure、external_references、issues
- **还需补充**：单元规划、回填位置、已有译文、目标接口和规则
- **应交付**：单元译文、回填对应、状态约束

**验证**

- **读取预处理材料**：handoff、inventory、input、issues、manifest
- **还需补充**：源侧可运行工程、目标实现及译文、构建命令、测试对应
- **应交付**：构建与执行日志、用例对应、失败及待验证事项


downstream_handoff.json现登记表中六类消费者，每类都有实际可用材料、待补输入、预期输出及专属prompt。它们是文件使用约定，执行者按约定调用各工具。公共材料与翻译单元规划仍在既有流程的对应环节完成。

所有模块先读capabilities。translation_features只提供有限语法提示；生命周期和重载适配结合框架绑定及目标规则确认。

## 3. 分模块使用方法

### 3.1 上下文查找

按当前任务的源文件和成员定位引用，再向被授权的上下文源查询。可复用预处理原文与语法索引，直接使用同一份原文。同名调用的目标由上下文或类型分析进一步消歧。

与既有上下文工具的重合点是输入定位和语法索引；检索、消歧与目标接口补充仍由上下文模块负责。执行者对接既有上下文工具时，传入源文件相对路径、成员位置及引用表达式，由该工具返回上下文和来源。

### 3.2 Java骨架提取

完整 input 文件交给现有提取器，members 用于核对原文和位置。保留类型、构造器、字段、初始化块、辅助方法与框架注解。占位格式由骨架提取器决定，预处理保留完整原文。

若提取器只接受项目路径，应确认支持缺少业务实现的语法提取模式；工程编译时补齐业务实现与构建依赖。依赖类型绑定的提取器需另行满足其输入条件。

### 3.3 仓颉骨架生成

结合目标接口和类型对应生成声明与填充位置。源声明索引可以复用，目标骨架依据接口与类型对应生成。Java重载和构造器是否需要适配由该模块结合仓颉能力决定，预处理保留原构造器和重载结构。

返回源文件、原成员位置、目标文件和填充位置映射；接口不足时登记缺项，由接口来源补齐业务条件。

### 3.4 整体翻译

读取完整测试类型与相关辅助类，核对字段初始化、准备、清理、参数化数据及资源访问。候选列表用于导航，翻译范围覆盖所选完整测试及辅助成员。引用需要进一步确认时向上下文或接口模块补充信息。

例如测试创建 Calculator、调用 add(1, 2) 并断言为3。预处理保留全部表达式；翻译模块取得目标类型、初始化与 add 接口后完成翻译，翻译时保留原调用与期望值，并通过接口补充解决缺项。

### 3.5 片段翻译

先用成员索引规划单元，再读整文件确定字段与前序状态。成员作为翻译素材，其执行条件通过整文件及补充上下文取得；涉及同一测试状态的片段须共同规划初始化与回填。

例如先 list.add(1) 再断言 list.size() == 1，后半段沿用前序操作产生的列表状态。保持语句顺序和同一实例状态，并向回填模块交代约束。

### 3.6 验证

先检查字节、区间和摘要，再在完整源目标环境中构建执行。源工程运行时补齐业务实现和构建配置。分别记录静态材料检查、编译、测试执行、语义比较和检错能力，每一层分别给出结果。

## 4. Agent调用

向 Agent 提供整个本轮目录、职责、任务范围和额外输入。先读 handoff.prompt 的共用约束，再按downstream_handoff中本模块prompt读取专属要求和本文对应段落。将以下模板的尖括号内容替换为实际值：

```text
你负责<模块名称>，预处理结果根目录为<结果路径>。
先读 handoff.json、issues.json、交接提示词.md、下游模块使用说明.md。
只执行下游模块使用说明中与你职责对应的部分。
任务范围：<源文件或成员及目标要求>。
额外输入：<目标接口、规则、骨架、上下文源等路径；缺失则注明>。
输出目录：<冻结结果之外的新目录>。
先登记缺项；可独立开展的部分继续处理，依赖缺项的部分标记为待补充。
返回 source_snapshot_id、所用文件与成员定位、补充输入来源、产物位置、
待确认项及实际验证。保留冻结输入和原断言要求，登记并补充缺项。
```

执行者使用以下专属提示词组织模块任务，路径相对本轮结果根：

| 模块 | 专属提示词 |
| --- | --- |
| 上下文查找 | prompts/context.md |
| Java骨架提取 | prompts/java_skeleton.md |
| 仓颉骨架生成 | prompts/cangjie_skeleton.md |
| 整体翻译 | prompts/whole_translation.md |
| 片段翻译 | prompts/fragment_translation.md |
| 验证 | prompts/validation.md |

交接材料可用工具的check_handoff.py --run结果路径检查，按冻结结果执行材料核对。接入既有工具时按双方字段建立对应。

## 5. 返回与接收检查

建议返回交接回执.md，记录负责模块、source_snapshot_id、所用文件和成员、额外输入及来源、输出路径、缺项、实际验证与待验证事项。回执由执行者依据实际操作填写。

串联方对照：快照一致、目标接口真实提供、产物可定位回原成员、初始化与断言得到保留、缺项对下一模块的影响明确。依赖分析、骨架生成、源码转换及翻译效果按各责任模块的产物验收。
