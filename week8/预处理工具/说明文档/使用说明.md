# 使用说明

通过窗口选择输入、保存或载入设置，并查看预处理结果。

## 1. 环境要求

| 组件 | 要求 |
| --- | --- |
| Python | 3.10 以上；窗口需要 Tkinter；使用 Python 标准库 |
| Java | 完整 JDK 17 以上，包含 java 与 javac，建议来自同一 JDK |
| 源码 | Java 文件为 UTF-8；解析器按 Java 17 语法处理 |
| 系统 | Windows双击启动；窗口需要Tk与桌面环境，实机检查环境为Windows |

Python、JDK 使用标准安装或显式指定的路径，通过所选环境定位。终端可执行 python --version、java -version、javac -version 检查。Linux/macOS 根据安装情况使用 python3。

## 2. Windows 窗口运行

1. 完整解压到新文件夹，进入包含 README.md 和启动预处理.cmd 的目录。
2. 双击启动预处理.cmd。若要求选择解释器，在文件选择窗口中选择已安装的 python.exe；单独运行解释器会进入 Python 控制台。
3. 点击“使用随包样例”，或选择 Java 工程根目录，即包含 src/ 或各模块的目录。
4. 核对测试源码目录。标准 src/test/java 自动填入；多模块用“添加目录”逐个加入，例如 module-a/src/test/java。测试辅助类、基类所在测试目录也须纳入。
5. 核对测试资源目录。标准 src/test/resources 自动填入；可按资源情况留空。
6. 选择工程外的结果保存位置，窗口在其下新建带时间标记的本轮目录。
7. 点击“检查环境”。需要时用“选择JDK”指定包含 bin/java 和 bin/javac 的 JDK 根目录。
8. 点击“开始预处理分析”。结束后查看状态及日志，使用“打开本轮结果”或“查看本轮说明”。

运行中显示活动条，结束后收起，作为运行状态指示。期间输入控件锁定，结束后恢复。失败时保留日志并查看 FAILED.json（若已创建结果目录）。

### 2.1 已有配置文件时怎样载入

1. 双击根目录的启动预处理.cmd，进入工具窗口。
2. 点击窗口上方的“载入设置”。
3. 在“选择设置JSON”对话框中进入配置所在目录，例如工具内的主体/config。
4. 选中自己的local.json，点击“打开”。也可以在对话框的文件名栏粘贴该JSON的完整路径。
5. 观察工程目录、测试根和资源根是否已经填入。配置中的java、javac也会被载入；“检查环境”可核对所选JDK。
6. 核对“结果保存位置”。这里选择一个已存在、位于输入工程之外的父目录，工具会在其下新建本轮结果。
7. 点击“开始预处理分析”。载入配置只填入设置，点击开始后才执行分析。

### 2.2 怎样创建自己的配置文件

可以在窗口先选择工程、测试根、资源根、结果保存位置和JDK，再点击上方“保存设置”。选择保存位置，输入文件名local.json并保存。下次通过“载入设置”选中这份文件即可恢复选择。

个人设置保存到你选择的位置。再次使用时，点击“载入设置”选中同一文件。设置文件由窗口的“保存设置”功能生成。

## 3. 查看输出

每轮结果独立保存，交接时保留整个目录。

| 文件 | 内容 |
| --- | --- |
| `handoff.json` | 入口；snapshot_id、status、输入范围及各输出相对路径 |
| input/ | 测试 Java 与选定资源原字节副本，保留工程相对路径 |
| `inventory.json` | 已复制文件类型、路径及 SHA-256 |
| `members.json` | 成员原文、类型、注解、source_member_key及UTF-16区间，区间左闭右开 |
| `test_structure.json` | 类型、字段、初始化、方法与语法调用线索 |
| `test_candidates.json` | 按注解名称识别的候选 |
| `external_references.json` | 导入、调用及 resolution=NOT_ATTEMPTED 标记 |
| `issues.json` | 编码、语法及范围问题 |
| `capabilities.json` | 实际能力与模块职责 |
| `source_mapping.json` | 源路径、副本路径与相同摘要；源端恒等对应 |
| `translation_features.json` | 语法特性与注解名称提示，供下游确认 |
| `downstream_handoff.json` | 六类消费者的available、missing、expected及专属prompt路径 |
| prompts/ | 六类消费者的专属操作要求 |
| 下游模块使用说明.md | 消费方法，由 handoff.consumer_guide 指向 |
| 交接提示词.md | Agent 共用约束，由 handoff.prompt 指向 |
| 结果阅读说明.html | 本轮概览，由 handoff.report 指向 |
| `manifest.json` | 除自身外的输出文件摘要 |

窗口在本轮目录旁保存同名 .界面日志.txt，与冻结结果分开保存。snapshot_id 标记源材料快照；manifest 用于检查输出内容。input提供测试侧材料；工程装配时补齐运行依赖。

## 4. 状态与错误处理

| 状态或现象 | 含义与处理 |
| --- | --- |
| `ANALYZED_WITH_LIMITATIONS` | 分析生成，仍须阅读 issues 和待解析引用 |
| `PARTIAL_ANALYSIS_REVIEW_REQUIRED` | 有解析或编码问题，先确认受影响范围 |
| `NO_TEST_CANDIDATE_REVIEW_REQUIRED` | 未找到名称匹配候选，核对框架与范围，进一步核对实际测试范围 |
| `FAILED.json` | 本轮失败，读取 reason；修正后重新生成结果 |
| 启动出现 >>> | 打开了解释器本身，关闭后运行启动脚本 |
| 找不到 Python/Tkinter | 选择满足环境要求的解释器或安装对应组件 |
| 找不到 javac | 选择完整 JDK |
| 结果目录已存在 | 窗口自动新建轮次，核对结果保存位置 |
| 未找到测试根 | 指定实际目录；按声明范围采集 |
| `NON_JAVA_NOT_COPIED` | 源码根中的非Java文件进入问题清单，按用途补充资源范围 |

以上状态描述材料分析；构建、执行和行为验证按各自步骤记录。模块承接见[下游模块使用说明](下游模块使用说明.md)。


## 5. 下游接收

交接整个本轮结果目录。接收方先阅读handoff、capabilities和issues，再按downstream_handoff选择负责模块。材料的用途见[输出文件与字段使用说明](输出文件与字段使用说明.md)，各模块操作见[下游模块使用说明](下游模块使用说明.md)。
