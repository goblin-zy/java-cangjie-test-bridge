# Account 错误业务实现生成结果

来源：https://github.com/goblin-zy/java-cangjie-test-bridge，固定提交 `9b5b13e1dd02a026650f46185ab6a3ee093268d8`，材料版本 1.2.0。

本次依据 account.cj 和 account_test.cj 静态分析，生成12个独立错误版本。测试包含A01—A09九个方法，A05的prepareSequence辅助方法中的中间断言也已纳入分析。首批覆盖构造范围、存取款边界、状态更新、异常类型、校验顺序和查询返回值，未将修改常量的同类错误重复堆积。并未穷尽所有可能错误。

所有检测结果均为预测；未编译、未执行测试，也未计算检测保留率。未调用其他模型，这是本聊天按已定稿提示词执行的一次生成。

## 文件使用

- original/：从固定提交取得的原始业务与测试快照。Git blob哈希已核对。
- mutants/Mxxx/cangjie/src/account.cj：该错误版本的完整业务文件。
- mutants/Mxxx/change.patch：同一修改的补丁。完整文件和补丁二选一使用，不重复应用。
- mutants/Mxxx/错误说明.json：该版本的触发条件、源码依据与预测说明。
- 错误清单.json：全部版本的结构化清单及测试证据。
- 静态核对.json：文件与补丁核对证据，不是编译或测试结果。

每次从固定提交的完整原始项目单独复制一份，仅替换对应account.cj，或从项目根目录独立应用一个change.patch。其他文件与原测试保持原样。不要把多个错误版本叠加，也不要把多个Account定义同时放入同一个包。目录内只包含本次Account材料，不是完整可运行项目。

## 预测解释

- M001、M005、M009：合法边界操作被错误拒绝，相关测试可能以非预期异常结束，而不一定产生普通断言失败。
- M006：参考测试只捕获InsufficientFundsException；换成IllegalArgumentException后预计会出现未被该catch捕获的异常。不能将其记成已经发生的测试结果。
- M007、M008：零金额不再抛异常；余额虽然不变，异常标志的断言预计发现偏差。
- M010：唯一根因是将存款状态更新移到校验前。非法存款-1会先改变余额；接近上限时，容量检查还会观察到已更新余额。这些是同一顺序错误的后果。
- M011：唯一根因是将扣款移到校验前。失败取款会污染余额，余额不足判断也会使用已扣减余额。A05现有正常序列预计仍通过，因此未列入预计检出测试。
- M012：余额查询固定返回0，A04恰好期望0，预计不会由A04发现；A09不调用余额查询，预计也不受影响。
- 关联测试列表用于预测检出关联，不是已经运行的结果矩阵。@Expect可能在一次检查失败后继续执行，后续也可能出现异常；没有实际执行时不臆造最终失败/错误数量。
