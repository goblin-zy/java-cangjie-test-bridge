依据：本次用户完整实施要求，以及 Obsidian《实现项目约定与公共材料生成工具 的说明介绍》《大概流程》《第七周》。本文件记录实现状态，不是实验结果。

## 约束与决定

- 目标目录初始为空；上层没有 Git 仓库，直接在用户指定目录工作，不初始化或改动其他仓库。
- 用户明确要求本阶段不编写、不运行测试，优先级高于执行技能中的 TDD 流程。仅允许依赖准备、工具自身构建和基础静态检查。
- 采用 executing-plans 的分项执行及记录方式；不运行其 Git 专用脚本，不生成虚假的测试/提交记录。
- 不运行样例项目，不把目标参考测试作为输入。无模型 API、无全局 Skill 安装。
- Python 3.11+ / Pydantic 2.10.3 / SQLite；JavaParser 与 SymbolSolver 独立 Java 助手；仓颉官方 std.ast 助手通过版本化 AST dump 桥接，语法解析不等于类型解析。
- JDK 实际发现于 C:/Program Files/Java/jdk-17，Java 17.0.8；PATH 上 Oracle Java 跳转入口启动异常，应显式配置工具路径。未发现 cjc/cjpm，仓颉助手不能在本机构建，必须如实报告。

## 分项与接口

1. 数据模型和 SQLite：文件快照 → 成员、引用、事实、问题、对应候选。稳定 ID 基于来源根别名、路径、完整成员定位；重复定义保留歧义。
2. 解析助手：输入文件清单 → 版本化结果。Java 输出 JSON；仓颉 std.ast dump 由 Python 解码并归一化；不以正则解析源码结构。
3. 收集、配置、候选和证据包：扫描只读输入、存完整内容和哈希；源目标候选永不自动确认等价；查询使用快照。
4. Codex 材料草稿、合并、校验和 Markdown：十一类共享模型；直接事实与 AI 推断分开；来源校验、冲突清单；可确定地由 JSON 导出同内容 Markdown。
5. 工作流与入门文档：命令、配置、完整提示词、错误处理、支持范围及未做测试声明。

接口约束：解析器的行号必须指向扫描快照；证据包不得超预算静默截断；扫描版本变化会使旧 AI 草稿失效；合并时不能静默覆盖人工条目。
