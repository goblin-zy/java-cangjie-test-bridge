# 测试样例与核对记录

日期：2026-11-04。本工具集成至蒋逸舟week7分支；评价工具与论文研读保持原内容。

## 1. 团队仓库原有账户测试

输入采用工作区中团队Java项目的完整week7目录，测试文件为src/test/java/study/translation/AccountTest.java。工具只根据项目结构及目标标识查找，不使用账户专用选择配置。

实际输出位于actual/account-method和actual/account-class。方法目标为testSequence()：应找到字段account、setUp、prepareSequence、辅助方法内两次断言、存取款实现及必要异常定义。类目标则覆盖该类9条原测试；整体保留类文件不等于每个成员都参与单个方法。

框架assertEquals及JDK异常不展开源码，原调用及停止原因保留在未解析项中。没有重新运行Java或仓颉测试。

## 2. 独立多模块工程

examples/projects/多模块测试工程是新编语法/依赖查找夹具，含core业务模块、checks测试模块、父类准备和清理、类外辅助断言、静态常量、实际资源、接口、同参数数目重载及递归调用。history下额外保存同名历史源码副本，用于检查范围发现是否误收集。

实际输出位于actual/multi-module-method和actual/unresolved。正常方法应保留父类生命周期、辅助断言、被调用业务及price.txt实际内容；诊断方法应报告动态资源路径、重载歧义和接口实现未确定。

该夹具含有意设计的无法执行或不应运行的诊断方法，仅用于查找验证，未宣称构建或运行基线通过。

## 3. 可复用性与内容核对

测试切换目标类、文件路径及方法标识，验证无关辅助方法不被标为当前展开成员；在临时重命名的工程中重复执行，路径和类名不绑定账户样例。另覆盖平面JUnit4工程、中文/emoji/CRLF、二进制资源、递归、查找上限及错误目标。

对输出代码逐条用来源UTF-16范围重新截取，核对实际内容和文件摘要；检查Markdown展示同一批材料。资源与源字节一致，非文本可从Base64还原。具体自动测试结果见validation。
