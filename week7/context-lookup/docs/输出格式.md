# 输出格式

## 顶层字段

|字段|内容|
|---|---|
|target|项目、测试类、当前测试方法及文件|
|scope|实际源码/资源根、索引范围、限制参数和停止条件|
|original_tests|当前查找的原始测试方法代码及位置|
|related_members|按来源文件列出本轮实际展开的成员候选|
|records|按类别保存代码与资源内容|
|unresolved|未解析引用，含实际引用代码、位置、原因及候选（适用时）|
|boundaries|可解释的停止边界，例如隐式默认构造|
|project_issues|构建路径、编码或其他源文件解析问题|
|limitations、completeness|能力边界及完整性状态|

## 每条上下文记录

包含id、category/categories、content、source和reasons。source记录项目相对路径、行号、UTF-16起止位置及来源文件SHA-256；reasons记录查找原因及由哪个成员引入。

资源记录额外包含encoding。UTF-8文本直接保留内容；Base64表示完整二进制字节，不是资源内容摘要。资源不适用的源码偏移不伪造。原始文件SHA用于核对来源，不等同语义正确性认证。

## 完整测试类与相关标记

original_test_class保留完整类，包含其他测试和周边成员。related_members表示本轮实际纳入和展开的成员候选，不表示完整类中的每个方法都与目标有关。字段和初始化采用保守保留，相关理由会明确说明，未进行最小依赖证明。

## JSON与Markdown

两份文件从同一结果对象生成，Markdown按原始测试类、导入、字段初始化、生命周期、辅助方法、业务依赖和资源等类别展开实际内容，并列出相关成员及未解决项。源码中的CRLF在Markdown显示时统一为换行；JSON保留截取内容与原字节对应的位置和摘要。

未解析的框架断言调用仍出现在辅助方法原代码中，因此不会因框架源码不展开而删除断言要求。具体无法解析的调用均按出现位置记录。
