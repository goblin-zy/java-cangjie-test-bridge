# 上下文查找与可执行性评价：操作教程

负责人：蒋逸舟。以下命令均在**完整Git仓库根目录**的PowerShell执行，不是在context-validation目录执行。

## 0 准备与确认目录

打开克隆的java-cangjie-test-bridge文件夹，应同时看到week7/src和week7/context-validation。需要Python3.9+、JDK17+；只做上下文不需要Maven、JUnit依赖下载、仓颉SDK或模型API。

```powershell
python --version
java -version
javac -version
```

如果只有py命令，将后文python改成py -3。若本机Python不在PATH，可用完整解释器路径代替python；JDK同理可在index命令末尾增加--java和--javac完整路径。仓颉评价另外需要已准备好的Windows SDK1.2.0。

## 1 先看提交的现成结果

打开[普通取款](../validation/context/export/context_01.md)、[辅助准备与连续操作](../validation/context/export/context_02.md)、[余额不足](../validation/context/export/context_03.md)。

每份都有完整原测试类、当前测试、显式选入的字段/准备/辅助/业务/异常代码、来源和选择理由。JSON是同一批材料的机器记录。它不包含仓颉参考答案。特别检查辅助方法里的中间断言与异常后继续合法取款，不要只看最终余额。

## 2 对当前仓库重新建立索引

```powershell
python week7/context-validation/tools/context_lookup.py index --output week7/context-validation/runs/index-01
```

该命令编译并调用week7已有JavaTestSkeletonExtractor，对src/test/java和业务目录生成两组members.json，然后整理catalog.json与index.md。不会运行账户Java测试，也不会重新发明成员标识。

打开runs/index-01/index.md，找到study.translation.AccountTest#testWithdraw()。catalog.json保存upstream_id与源片段，test-members/members.json保存上游完整格式；源码原副本与骨架也随索引保存。当前src/test/java包含提取器自测，其成员可能进入索引，但不计入九条账户业务测试。

## 3 按已有选择方案导出上下文

```powershell
python week7/context-validation/tools/context_lookup.py export --index week7/context-validation/runs/index-01/catalog.json --selection week7/context-validation/examples/account/selection.json --output week7/context-validation/runs/context-01
```

成功时列出三条目标方法，检查条目数分别为10、12、10。打开runs/context-01/context_01.md及同名JSON，再看checks.json。inputs/保存本次实际使用的Java源文件；selection.json冻结本轮选择。

selection.json中的group区分test/main，symbol沿用上游限定类型与签名，reason解释为何选入，use说明怎样供翻译使用。当前示例为Codex协助拟定，蒋逸舟待审核。你可以复制此文件修改选择理由、添加或删除依赖，再导出到新目录；不能把示例当作自动查找结果。

## 4 亲自检查工具的限制

先复制selection.json到runs/selection-missing.json，选择一个evidence条目，把symbol改成不存在的名称。使用同一个索引、指定新的输出目录导出，程序应失败并报告Selected member not found，不能编造代码。

如果索引后源码变化，导出应报Stale index or changed source；重新索引并重新审核选择，不要删除哈希检查。输出目录非空也会被拒绝，重跑用index-02/context-02等新名称。

若删掉一个实际需要的evidence条目，程序可能仍能正常导出：它只能验证你选择的片段真实存在，尚不能证明依赖完整。完整测试类也会保留部分被删的测试类成员，因此此实验只说明选择标记缺失，不一定真的从输入删掉该代码。要研究遗漏影响，需冻结真正给翻译者的输入后再比较候选，不能把导出PASS当作没有遗漏。

## 5 怎样交给翻译环节

提交选定的上下文、完整原测试、既有规则/接口映射和待填目标骨架，并说明允许修改的位置。下游按实际使用的文件和版本生成首轮候选；不要把仓颉参考测试当作生成结果。准备、异常类型、辅助断言有缺口时先反馈负责人确认。

当前接口对接见[接口和输出格式](接口与输出格式.md)。资源、继承、动态分派、完整类型解析仍需另行处理；不知道时写未解决项。

## 6 对当前仓库九条仓颉参考测试做评价

本例先用已存在的reference检查评价工具和环境，**不是生成翻译结果**。将SDK路径改为自己的实际目录：

```powershell
python week7/context-validation/tools/evaluate_account.py --sdk-root 'D:/CangjieSDK/cangjie' --runtime-label '填写实际运行库版本与localfix情况' --output week7/context-validation/runs/account-evaluation-01
```

仓库既有验证环境是SDK1.2.0配合localfix。原版环境是否能运行需实际判断，不要因失败就修改业务或断言。本入口记录SDK编译器及runtime DLL摘要，生成九条方法清单后调用通用评价脚本。

先看runs/account-evaluation-01/execution/report.md，再看results.json及各阶段日志。预期9、发现9、执行9、通过9才是本示例完整通过；零执行、过滤遗漏、测试错误和环境失败分别报告。run_metadata.json保存负责人、辅助执行说明与运行库信息。

换成自己的候选：复制本次config.json，修改business/tests/expected_tests，并将sdk_root改为本机SDK，再调用：

```powershell
python week7/context-validation/tools/cangjie_runner.py --config '你的新配置.json' --output week7/context-validation/runs/candidate-01
```

相对源码路径从配置文件所在目录解析；expected_tests是目标仓颉方法标识，不是上游Java成员ID。不要将normal和故障诊断组合混为同一个成功率。

## 7 不安装仓颉也能核对已提交证据

```powershell
python -m unittest discover -s week7/context-validation/tests -v
python week7/context-validation/tools/check_delivery.py
```

应看到7项测试通过，以及all_passed:true、169项核对通过。后者只读取已有报告、快照和CSV/JSON/Markdown，不重新执行仓颉，也不读取原作者电脑的历史绝对路径。
