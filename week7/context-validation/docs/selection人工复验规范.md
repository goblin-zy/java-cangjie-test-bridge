# selection.json 人工复验规范

## 1. 依据与范围

本规范是项目内审查准则，不是通用语言标准或语义等价证明。判定顺序为：**同版本Java原始测试及业务源码 → 已确认的项目约定与目标接口 → 索引及导出记录**。索引用于定位，不替代源码；成员命名、模型说明和导出PASS均不足以证明依赖完整。

框架生命周期与断言语义按项目实际使用的JUnit版本核对；涉及仓颉表达时另查已确认的接口映射和对应版本语言/测试框架文档。框架版本、接口或项目约定缺失时列为待确认，不按经验补齐。当前样例从`week7/src/test/java/study/translation/AccountTest.java`出发，不采用早期五条/两条账户样例的名称、输入与异常约定。

## 2. 复验清单

|编号|检查对象|复验方法|通过条件|
|---|---|---|---|
|R1|版本与来源|比对索引、现场源码、快照哈希及目标清单|版本一致；目标逐项对应；无旧索引混用|
|R2|标识与格式|检查schema_version、非空units、group/symbol及reason；核对索引中的限定类型和签名|目标为当前支持的普通@Test；无不存在、歧义、重复目标或重复证据；元数据真实|
|R3|操作前状态|沿字段初值、构造、准备方法及其调用继续追踪|能由源码解释每条测试执行前的对象与状态；不将字段初值等同于准备后的状态|
|R4|操作与依赖|逐个检查实际调用、字段读取、常量、异常及辅助方法|相关定义已选入或明确说明不展开的原因；不只凭方法名确定依赖|
|R5|断言与控制流|列出观察对象、输入、期望、断言范围和顺序，包括helper内部断言|普通断言、异常检查、中间状态及异常后续操作均有依据；没有删减或放宽要求|
|R6|未知与排除项|核对资源、继承、清理、动态绑定、JDK/框架和外部依赖|无法确认的项进入unresolved，并说明对本轮使用的影响|
|R7|输入边界|核对实际读取文件及最终给下游的材料|未混入仓颉参考测试答案、其他版本样例或未经确认的接口；完整输入可恢复|
|R8|导出与复验记录|检查context JSON/Markdown、inputs、冻结selection及checks|源码与片段一致；程序结果和人工结论分别保存；未覆盖旧记录|

### 当前三条目标的重点

- `testWithdraw`：核对`setUp()`所建立的初始状态、取款参数、余额查询对象及预期值。
- `testSequence`：展开`prepareSequence()`，逐条核对存款、取款与中间断言，再核对测试末尾操作及断言。
- `testInsufficientFunds`：核对`InsufficientFundsException`的具体类型、异常检查所包围的操作、异常后的状态与后续合法取款。不得替换成早期样例的`IllegalArgumentException`。

预期值以当前冻结源码为准；不是按示例输出条目数凑出10、12、10。该数量包含目标方法和完整测试类各一条，加显式evidence，不能用来判断选择是否充分。

## 3. 结论与记录

在新目录保存`review.md`，记录审查人、日期、源码版本、catalog与selection摘要、目标清单，以及R1—R8的结论、证据位置、问题和修订意见。状态使用：`通过`、`需修订`、`待确认`；尚未审查的项目不得写为通过。

```text
审查人／日期：
源码版本／索引路径及SHA-256：
selection路径及SHA-256：
目标清单：
R1—R8：结论／源码位置或输出路径／问题
未解决项及对当前任务的影响：
总体结论：通过／需修订／待确认
修订内容与复验记录：
```

来源或片段错误、必要准备缺失、断言遗漏、答案泄漏均应修订。影响测试含义的依赖仍无法确认时，保留待确认结论，不将材料作为已通过审核的翻译输入。

审核前保留`human_review: PENDING`。审核完成后可在**新修订的选择文件**中如实记录`PASSED`并关联审查记录，再导出到新目录。该字符串仅为人工声明：当前程序原样传递，不验证审核身份或审查充分性；`checks.json`中的审核字段仍固定为PENDING，不应手改成自动认证结果。源码或选择变化后需重新核对，不能沿用旧审核结论。

## 4. 两个容易误判的情况

删掉`prepareSequence()`的evidence，导出仍可能PASS，因为程序只核对已选成员，且完整测试类内可能仍含该方法。R4、R5仍须指出显式依赖标记缺失；要研究实际遗漏影响，还需核对真正提交给下游的文件内容。

为每个成员填写“翻译需要”虽可满足非空reason检查，却没有解释依赖关系，不满足R4。应写明调用者、涉及的状态或断言，并给出源码位置。
