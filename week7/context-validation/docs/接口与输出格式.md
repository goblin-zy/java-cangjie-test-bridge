# 接口、格式和共同约定

负责人：蒋逸舟。

## 上游输入

依赖week7/src/main/java/JavaTestSkeletonExtractor.java及其schema_version=1.0的members.json契约。默认测试根是week7/src/test/java，业务根是week7/src/main/java/study/translation；index支持--test-root/--main-root指定仓库内其他源根，不绑定Account类名。更换布局时须重新审核选择方案。

上游id格式为相对文件::包.类#成员(参数类型)，字段使用#field:名称，构造器使用#<init>。保留原始upstream_id，不删掉文件前缀作为唯一主键。catalog中的group+symbol用于选择；同组重复限定符号会拒绝，避免静默覆盖。

source_location偏移为UTF-16代码单元，结束位置不包含该位置。工具按UTF-16切片，不能直接用Python字符下标；已检查中文、表情和CRLF场景。source.file为导出包可解析路径，source.location.file保留上游原位置语义，不应直接从导出根解析它。

## 索引输出

- catalog.json：schema_version=context-catalog-1.0，files记录源根对应仓库路径、快照、包、导入、SHA256；members/classes保留上游身份、角色、位置和实际片段。
- test-members/、main-members/：真实上游original、skeleton、members.json与报告；input_root元数据改为仓库相对路径，成员id和偏移不变。
- index.md：从同一catalog生成的成员列表；不表示依赖选择完成。

## 选择输入

examples/account/selection.json是完整可用示例。schema_version=context-selection-1.0；units非空，target包含group与symbol；evidence每项包含group、symbol、非空reason；use解释使用方案；unresolved列未解决项。selection_author说明选择来源，human_review在人工确认前为PENDING。

当前普通@Test可作为目标。参数化、重复或动态测试不自动展开。相同目标重复、找不到符号、歧义、源码变化和非空输出均拒绝。

## 上下文输出

每个目标产生context_序号.json与同名.md，schema_version=test-context-1.0。target、original_test_class、context包含原代码、上游标识、角色和可定位来源；imports保留源导入。JSON、Markdown来自同一数据，checks.json说明源码位置与内容核对。

inputs保留实际源文件字节。catalog_sha256和selection_sha256固定实际输入版本；选择文件另存selection.json。resource_status=NOT_ANALYZED和dependency_completeness=NOT_ESTABLISHED不等于没有资源或依赖完整。完整所在测试类可能含未标为相关的其他测试成员，这是有意保留供核对；不声称已得到最小上下文。

## 下游评价接口

cangjie_runner.py接收--config和--output。单组必填id、business、tests，以及expected_tests或expected_count；sdk_root为顶层环境配置。批量使用combinations。相对源码路径从配置父目录解析；每组id批内唯一；输出必须新目录或空目录。

九条示例直接读取week7/reference/cangjie/implementation/account.cj与tests/account_test.cj。目标包为starter，方法标识示例starter.AccountTest#testWithdraw()，与Java的study.translation.AccountTest#testWithdraw()通过显式映射对应，不进行同名猜测。

输出schema、字段、分母和分类见[评价输出格式](评价输出格式说明.md)及[评价方法](评价验证方法与交付说明.md)。配置、环境、源码快照和分阶段日志随结果保存。null表示未取得，0表示已确认零项；缺依赖、环境失败、跳过、执行错误和断言失败分别处理。

业务角色normal用于正常组合统计，diagnostic用于故障诊断。执行通过不证明Java与仓颉语义等价。缺少目标实现不能用骨架编译替代真实业务验证。
