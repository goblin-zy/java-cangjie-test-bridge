# 执行评价输出格式

## 1 层次与共同约定

单组合schema_version为cangjie-execution-v1，批量为cangjie-execution-batch-v1。时间为带时区的ISO格式。源码快照路径相对组合目录；日志路径相对其命令记录目录；原始文件、工作目录及命令cwd为运行时绝对路径。迁移目录后旧绝对路径只用于追溯，重新运行必须更新配置。

## 2 单组合result.json

| 字段 | 含义与必填约定 |
| --- | --- |
| schema_version / combination_id / business_role | 必填，版本、组合标识及用途 |
| started_at / finished_at / status / message | 必填，时间、主要结论与原因 |
| compile_status | 必填，NOT_RUN、PASSED、FAILED、TIMEOUT或ENVIRONMENT_ERROR |
| expected_count | 必填，可为null；通常由清单长度或数量输入取得 |
| discovered_count | 必填，可为null；发现阶段确认的总数，包含跳过 |
| executed_count | 必填，可为null；通过、失败和错误之和，不含跳过 |
| passed_count / failed_count / error_count / skipped_count | 必填，可为null；分别为通过、断言失败、测试异常和跳过 |
| compile_exit_code / discovery_exit_code / run_exit_code | 必填，可为null；未运行、启动失败或超时时不伪造退出码 |
| expected_execution_ratio / pass_rate_executed / expected_pass_ratio | 必填，可为null；公式见验证方法；值为0到1比例，数量模式不限制超过1 |
| sources | 必填数组；每条role、original_path、snapshot、sha256。收集失败或环境失败可为空 |
| source_integrity | 必填，运行完成时原文件是否仍与快照哈希一致；未收集为null |
| stages | 必填对象；包含已尝试的compile、discovery、run，尚未尝试的键不出现 |
| missing_expected / not_executed_expected / unexpected_executed | 必填数组；确定未发现、未执行、清单外执行的方法 |
| limitations | 必填数组，当前结果的适用边界 |
| expectation_mode / expected_tests | 预期校验完成后出现；names或count；仅数量模式清单为null |
| discovered_tests / cases | 有可信发现或运行结果时出现；命名发现列表及方法→PASSED/FAILED/ERROR/SKIPPED映射 |
| discovery_identity_complete / run_identity_complete | 阶段可解析后出现；名称与数量是否完整对应 |
| unidentified_discovery_skips / unidentified_run_skips | 对应阶段有数据时出现；已知跳过但未能取得名称的数量 |
| unresolved_expected_in_discovery / unresolved_expected_after_run | 名称缺口下尚不能确定是否对应的预期项，区别于确定不存在 |
| resolved_expected_tests | 能对应到实际规范标识的预期清单 |
| report_source | xml_with_console_cross_check或console_summary_zero_execution；后者仅允许确认零执行，不允许判PASSED |
| working_directory / compile_options / run_options | 收集或选项校验完成后出现，保留实际工作条件 |

同一数组可能先在发现阶段有未解析项，再在运行XML中补齐；应读取阶段标志，不把旧阶段缺口当作最终遗漏。若无法确认全部结果，数量和比例保留null。

## 3 命令和日志

每个阶段*.command.json记录argv数组、cwd、起止时间、耗时、exit_code、timed_out、launch_error及stdout/stderr/readable路径。*.stdout.log和*.stderr.log保留原始字节，*.log是去颜色后的可读文本。环境报告只保存与工具链有关的选定环境字段，不导出全部环境变量。

XML原文同时保存，以便核对类型、用例和失败信息。正常运行数量以XML与终端完整汇总一致为前提；报告缺失、数量矛盾或不支持的名字格式单独报错。

## 4 状态分类

| 类别 | 状态 |
| --- | --- |
| 完整通过 | PASSED |
| 材料或环境 | INVALID_INPUT、INVALID_EXPECTATION、ENVIRONMENT_ERROR |
| 编译 | COMPILE_FAILED、COMPILE_TIMEOUT、BUILD_ARTIFACT_MISSING |
| 发现 | DISCOVERY_ERROR、DISCOVERY_TIMEOUT、NO_TESTS_FOUND |
| 运行或报告 | RUN_TIMEOUT、RUNTIME_ERROR、REPORT_MISSING、RESULT_PARSE_ERROR、RESULT_INCONSISTENT |
| 已取得测试结果 | ZERO_TESTS_EXECUTED、TEST_ERROR、ASSERTION_FAILED、TEST_SET_MISMATCH、TEST_COUNT_MISMATCH |

NO_TESTS_FOUND表示没有发现任何测试；ZERO_TESTS_EXECUTED表示发现测试但均未实际执行。TEST_ERROR属于测试方法抛出未预期异常，RUNTIME_ERROR偏向进程或报告异常。多个问题共存时status保留先判定的主要问题，数量、列表及日志保留其余事实。

## 5 批量与CSV

results.json必含schema_version、created_at、config_file、combinations、combination_count、compile_attempted、compile_succeeded、compile_success_rate、normal_combinations、normal_combination_pass_rate、all_combinations_passed和scope。比率无分母时为null。

CSV列为combination_id、business_role、status、compile_status、expected_count、discovered_count、executed_count、passed_count、failed_count、error_count、skipped_count、compile_exit_code、discovery_exit_code、run_exit_code、expected_execution_ratio、pass_rate_executed、expected_pass_ratio。空单元格对应JSON的null，CSV不承载完整代码、逐用例列表和日志。

Markdown按同一组合顺序展示主要数量和状态，未取得数据写“未取得”。需要精确字段或机器处理时以JSON为准，遇到不一致先核查生成和版本，不能任选有利数字。
