负责内容：Java测试骨架提取、参考仓颉测试。

## Java测试骨架是什么

Java测试骨架是从原测试源码中保留下来的结构框架：包名、导入、类声明、字段及其初始化、方法签名和注解仍然保留，方法体中的操作与断言则被替换为明确占位。被替换的原方法体另行保存，便于后续对应、翻译和回填。

它保留的是Java结构，目前还不是仓颉代码，也不能作为通过测试的程序直接运行。

### 为什么要提取

为后续按成员翻译提供结构与定位依据：先识别一个类里有哪些测试、初始化方法和辅助方法，再通过成员ID找到相应的原始代码，并将翻译结果关联回正确位置。提取器本身负责结构拆分和记录，不负责调用大模型翻译。

### 账户测试的前后对照

以AccountTest中的取款测试为例，下面省略包、导入和类外壳。原测试由@BeforeEach方法先创建余额100的账户，随后执行：

```java
@Test void testWithdraw() {
    account.withdraw(30);
    assertEquals(70, account.getBalance());
}
```

提取后，同一个方法在骨架中变为：

```java
@Test void testWithdraw() {
    throw new UnsupportedOperationException("SKELETON_PLACEHOLDER");
}
```

@Test和方法名得到保留，原来的取款操作与余额断言保存到members.json的original_body中。占位异常可以防止空测试被误认为通过；@BeforeEach初始化方法和辅助方法也会分别记录角色并保存原方法体。

### 本周交付了什么

实现方式：使用JDK的javac语法树接口定位声明和方法体，支持单文件及目录输入，不依赖固定业务类名。

|输出|作用|
|---|---|
|original/|保留输入源码的原始字节副本|
|skeleton/|保留结构、用占位异常替换方法体的Java文件|
|members.json|记录成员ID、签名、角色、原始方法体及源码与骨架的位置|
|extraction-report.md|列出提取成员及诊断、已知限制|

在现有三个业务测试类上共提取27个成员：24个测试方法、1个@BeforeEach初始化方法、1个辅助方法和1个字段。已检查方法体回填后与原文件逐字节一致，支持后续按成员交接。完整跨文件依赖和继承语义分析仍不在当前范围内。

## 本周主要步骤

1. 整理账户、矩形、指令解析三个Java业务类及其24个JUnit测试。
2. 使用JDK语法树实现测试骨架提取，保留声明和签名，保存原始方法体，输出骨架和members.json。
3. 验收单文件、目录、重载、嵌套类、构造器委托、语法错误和输出保护；检查原方法体能按位置回填。
4. 整理三个模块的参考仓颉测试，对照Java输入、操作与预期结果。
5. 编译执行参考测试，并用四种独立错误实现检查测试能否发现错误。
6. 将Java代码统一为Maven项目，配置VS Code测试入口；仓颉支持全部、按类和单项测试任务。

## 如何复现

1. 获取仓库，在VS Code中单独打开week7目录。
2. 安装JDK17及Java测试扩展，等待Maven导入，打开测试类点击Run Test。
3. 运行提取器时选择“提取业务测试骨架”，输入新的输出目录，检查骨架和members.json。
4. 仓颉需准备匹配的SDK及运行库，在工作区设置中修改SDK路径。
5. Ctrl+Shift+P → Tasks: Run Task → 运行仓颉参考测试（24项）或运行单个仓颉测试。
6. 单项输入AccountTest.testWithdraw；按类输入RectangleTest.*。详细步骤见附带文档。
