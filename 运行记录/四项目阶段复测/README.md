## 下一轮优化优先级

1. **静态验证支持多源文件。** JMustache 的 6 个执行入口在 MustacheTest，声明与 test/check 在 SharedTests。上下文能够关联，验证器仍只能在一份 Java 文件中插注释。建议以“文件身份＋区间”定位，分别输出带注释源码，并将跨文件辅助检查纳入同一单元。
2. **识别 AssertJ 链式检查与辅助断言。** Levenshtein 所选方法有十条 isEqualTo，但当前直接识别为零；JMustache 的检查在辅助函数。保留调用链与原文，补充检查依据及参数对应，不能把零当作没有断言。
3. **按选定测试控制材料体积。** 当前 suite 仍覆盖完整测试类，验证准备会复制其中全部材料；可按明确的选择器交付必要逐条文件、共享内容与补查入口，再测读取量和耗时。
4. **改进源码编码与失败诊断。** Commons Text 的 EntityArrays.java 在 UTF-8 编译中报错，上下文也记录该文件的解析/求解问题。本轮仅对所选距离实现编译真实依赖闭包，未转码；整个 Commons Text 工程构建尚未验证。

建议先做多文件验证，再处理 AssertJ；这两项已经有本轮真实受阻样例和可回归的输入。
