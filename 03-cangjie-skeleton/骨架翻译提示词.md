# Java 测试骨架翻译为仓颉测试骨架

请依据以下输入和处理要求，生成供后续整体填充的仓颉测试骨架，并建立可追溯的源目标成员对应。

## 一、输入

1. **本次任务配置。** 输入根目录、待翻译文件或成员范围、输出目录、目标包名、Java／JUnit／仓颉及测试框架版本、允许修改的文件、允许复用的目标代码。缺少影响生成的配置时，列出具体缺项。

2. **Java 骨架文件。** 读取提取器输出的 `skeleton/`，识别包、导入、类、字段及初始化、方法签名、注解和声明所属关系。

3. **成员信息和提取记录。** 读取 `members.json`、`extraction-report.md` 和必要的原始源码副本。核对成员 ID、角色、参数、返回类型、原方法体、源码及骨架位置、已有诊断。保留上游 ID，按提取器约定解释 UTF-16 偏移。

4. **第一类材料——通用转换规则。** 从 `translation_rules.json` 及规则说明中选择实际适用的条目，记录规则 ID、版本、适用条件和核验状态。
   - `SYNTAX-03` 用于包、导入和命名空间。
   - `TYPE-01/02/03` 用于字段及签名类型、数组和可空状态。
   - `OBJECT-01/02/03`、`FUNC-01` 用于字段、对象初始化、辅助成员和业务接口的关系。
   - `TEST-01/02` 用于测试类、测试方法、初始化、清理和生命周期。
   - 按需参照 `ASSERT-*`、`EXCEPTION-*`、`FUNC-02`，确认检查机制是否需要额外导入、类型或辅助声明。具体方法逻辑登记为后续填充项。
   - 遇到禁用、参数化、嵌套或继承等机制时，检查规则是否覆盖，未覆盖部分列为待解决项。

5. **第二类材料——项目约定与公共材料。** 读取同一快照的 `project_materials.json/.md`，核对来源、条目状态和冲突，并参照下列部分。
   - `C01` 确定文件、模块、包和依赖位置。
   - `C02/C03` 确定源目标符号对应、已有目标类型、参数、返回值和访问方式。
   - `C04` 确认影响声明的公共表示约定，具体测试数据仍归入局部上下文。
   - `C05/C07` 确认已有工厂、基类、公共辅助设施和允许复用的目标定义，区分仍需迁移的私有辅助成员。
   - `C06/C08` 确认依赖替代、工具链版本、测试宏和构建条件。
   - `C09` 按需确认资源相关字段、准备和清理声明。
   - `C10/C11` 确认修改范围、装配约束、支持范围和特殊处理决定。
   上述 C 编号采用项目材料的十一类目录，规则库的类别编号另按规则库解释。对候选、AI 推断和已确认记录分别保留原状态。

6. **第三类材料——当前测试上下文。** 读取相关的 `context_<标识>.json/.md`，核对源文件、上游 ID、哈希、选择理由和未解决项。
   - 从 `target`、`original_test_class` 核对当前成员和完整所在类。
   - 从 `context` 读取字段、初始化、清理、辅助方法、基类及必要业务定义，确定必须保留的声明。
   - 从 `imports` 了解源端依赖，结合目标接口材料确定导入。
   - 检查 `unresolved`、`resource_status`、`dependency_completeness` 和审核状态，记录尚未确认的依赖范围。

7. **必要的补充源码。** 当继承、重载、泛型、构造器委托、字段初始化或资源生命周期仍有歧义时，按来源位置读取原源码及允许访问的目标定义，记录实际补充范围。

## 二、处理

1. **校验输入。** 检查文件能否读取，成员表和骨架版本是否一致，规则与 SDK 版本是否适用，材料引用能否回到来源。登记冲突、缺项及受影响成员。

2. **梳理源声明。** 按文件和类列出字段、构造器、测试、生命周期、辅助方法和相关类型。记录注解、可见性、静态性、不可变性、参数和返回类型。单独列出继承成员的来源及生命周期关系。

3. **选择转换依据。** 语言和测试框架写法参照适用规则，项目专有类型和接口参照项目约定，成员关系与结构疑点参照真实上下文。为适配决定登记相关规则和材料条目。

4. **确定目标结构。** 决定包、文件、类、字段和方法签名，保留原测试的执行组织。生命周期适配要考虑执行时机、隔离与顺序。必要改名、类型变化及继承保留或展平要说明依据。目标接口缺失时标出受影响声明。

5. **建立源目标对应。** 为每个源成员登记目标文件、类、名称、签名和待填位置。复用已有目标成员时记录实际定义。一个源成员拆成多个目标声明时分别登记。新增辅助声明说明来源和作用，未解决成员填写阻塞原因。

6. **生成仓颉声明。** 输出必要导入和类成员。只有依据明确的简单常量才保留初始化值，需要后续迁移的初始化表达式登记为初始化槽并保存原表达式。采用 `Option` 等结构适配时记录目标类型和后续访问要求。

7. **设置待填位置。** 需要后续翻译的方法体使用明确占位异常，消息包含 `SKELETON_PLACEHOLDER` 和源成员标识。字段初始化槽单独记录。原操作、断言、异常预期和辅助方法逻辑保存在上游方法体及上下文，供整体填充使用。

8. **核对完整性。** 逐项检查遗漏、重复、目标名称冲突、注解和签名对应、必要辅助声明、外部类型依据、禁用状态。对参数化测试核对数据来源和展开关系，对继承生命周期核对执行顺序，未确定方案列入报告。

9. **记录检查事实。** 有环境且获准执行时保存编译命令、退出码和日志，测试发现用于核对声明与跳过状态。模型自检、程序检查、编译结果分别登记，未执行项标为 `NOT_RUN`。

## 三、输出

1. **仓颉骨架 `.cj` 文件。** 按约定目录给出完整可保存内容，采用实际目标包、必要导入和对应声明，每个待填位置有明确标记。

2. **成员对应表 `member_mapping.json`。** 使用 JSON 数组，每个对应项包含以下字段。
   - `source_member_id`，准确的上游成员 ID。
   - `source_members_file`，相对本次输出根可解析的成员表路径。
   - `source_location`、`java_skeleton_location`，保留源位置及偏移含义。
   - `target_file`、`target_class`、`target_member`、`target_signature`，目标定位和完整签名。
   - `target_line`，实际核对后的声明起始行，未准确定位时填 `null` 并说明。
   - `status`，采用 `mapped`、`reused` 或 `blocked`。
   - `fill_slot`，采用 `body`、`initializer` 或 `null`，多个目标位置分别列项。
   - `source_initializer`，原字段初始化表达式，没有时为 `null`。
   - `adaptation`、`rule_ids`、`material_refs`，记录适配理由及依据。
   目标标识要区分不同类与重载。新增辅助声明允许源成员 ID 为 `null`，同时登记其关联源成员和引入原因。

3. **翻译报告 `translation_report.json`。** 记录输入版本、实际读取范围、选用规则、类对应、声明及待填项数量、结构适配、未解决项和逐项自检结果。整体状态采用 `generated`、`partial` 或 `blocked`，与实际完成范围一致。

4. **程序检查与编译记录。** 保存实际取得的检查输出、命令和日志。未执行项填写 `NOT_RUN`，原始报错和受阻原因保留。

5. **交接说明。** 列出生成文件、可供整体填充的成员、尚需提供的目标接口或配置，以及影响装配的特殊决定。有文件写入能力时实际落盘，否则按文件名逐份输出完整内容并说明交付方式。
